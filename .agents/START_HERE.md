## 1. 宪法级原则：文档唯一归属铁律 (Exclusive Ownership Principle)

为了彻底避免文档冗余、模棱两可与多头维护，本项目文档遵循严格的**唯一归属原则**：

1. **唯一归属，严禁重复**：**任何一个概念、接口契约、业务需求或行为规范，在整个项目中必须且只能拥有一个唯一的归属文件**。
2. **禁止二次就地展开**：任何文档如需提及其他领域的内容，**必须且只能通过 Markdown 相对路径超链接引用其唯一归属文件，严禁复制粘贴或就地重新展开描述**。
3. **外部入口文件单句指针限制**：第三方 AI 编码工具在根目录创建的规则文件（如 `AGENTS.md` 等）必须且仅能保留单句重定向指引，严禁就地展开任何规则。

## 3. 标准化作业 4 步法 (Workflow Invariants)

在处理任何代码编写、功能扩展或维护任务时，必须严格遵守以下顺序：

1. **第一步（前置阅读）**：查阅上述导航矩阵，阅读任务相关的唯一归属技术文档，建立全局视角；
2. **第二步（方案输出）**：根据技术规范输出实施方案，**方案中必须单独列出“触碰的官方文件清单及预计改动行数”**，严格证明符合单行尾挂载要求；
3. **第三步（强制阻断）**：**停止所有工具调用，等待用户明确确认**，严禁未经确认直接修改代码；
4. **第四步（执行闭环与门禁）**：
   - 用户批准后执行修改；
   - **文档同步**：若任务涉及新增页面、挂载点变更或模块规格变动，**必须在同一个任务中同步更新 [overview.md](specs/overview.md) 注册表与对应 [features/](specs/features/) 规格文档**；
   - **代码质量与工作区零污染自查**：交付前必须运行构建或类型检查，并调用 `git status -s` 清除所有临时测试文件与脏数据。
